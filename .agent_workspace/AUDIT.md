## 一、已有循环盘点：哪些够用

结论先行：**「活下去」的压力面是完整的、数值自洽的、工程质量高；
「为什么活下去」的内容面几乎为零。** 现状是一台调校良好的生存计时器，
不是一个浮岛基建游戏。

### 1.1 够用（不要重写，扩展只做加法）

| 循环 | 现状 | 判定 |
| --- | --- | --- |
| 拾荒 | 开船（WASD/触摸摇杆）→ 靠近漂浮物出高亮环 → 空格/点按捞取；4 类材料按权重刷新、区间产出、45s 超时下沉淡出催促；捞取冷却 0.22s、水花、音效、HUD 数字 pop 全闭环（`world/junk.ts` + `entities/skiff.ts`） | **够用**，手感闭环完整 |
| 建造 | 1–5 选建筑 → 幽灵格预览 → 邻接/空地基/花费原子校验（位置先于价格）→ 拒绝短句 `placeHint` 上 HUD；空地基升级不洗血（`sim/rules.ts`） | **够用**，作为地基层很稳 |
| 生存压力 | 人口 = 3 + 每座产出建筑 1（盖房即多一张嘴），持续水/粮消耗；断粮单计时器 25s 宽限、喂饱 2× 回落；岛民每 2s 花 1 木板自动维修最残格（`sim/economy.ts`） | **够用**，收支设计有巧思（扩张自带代价） |
| 威胁 | 风暴 4s 预警 → 外圈一次性 22 伤，频率/落点数随时间递增；海盗按波、同波聚方位、速度血量成长、死掉金属；炮塔单发制 DPS 18（`sim/threats.ts`） | **够用**，难度曲线成立，事件出口（`ThreatEvent`）是现成的扩展挂点 |
| 元循环 | 天数计分（120s/天）、最长存活/局数/累计拾荒落 localStorage（`cww_sea_v1`）、结算死因双路文案 + 再来一局 | **最小可用但薄**——唯一复玩钩子是「破天数纪录」 |

### 1.2 工程底座（扩玩法的红利，务必复用）

- sim 全部纯数据 + 纯函数、不碰 DOM，Node 直接单测；确定性 RNG（mulberry32 +
  junk 的可持久化 LCG），探针指纹可复现。
- `data/constants.ts` 已是唯一数值真源（Round 3 opus-core 收编完成）。
- `updateThreats` 返回事件数组、session 分发音效——**剧情/任务触发器照抄这个模式
  即可**，不需要发明新总线。
- headless `Session`（`applyProbeAction`/`snapshot`）意味着新循环可以无浏览器验收。

## 二、缺什么：「只有一张木筏在漂」的五个根因

对照品类（益世界《疯狂水世界》一类休闲浮岛基建）的体验支柱逐条对：

### 2.1 物品辨识 —— 缺口最大

现状：全游戏可获得物 = 4 种建材 + 水 + 粮，**6 个数字**。漂浮物只有
4 种皮（木板/塑料/金属/绳索），捞 100 次体验完全相同。
品类的核心快感是「捞起一件东西，认得出它是什么」：罐头、旧收音机、
渔网、密封木箱（开箱惊喜）、漂流瓶（剧情载体）。当前没有条目、
没有稀有度、没有「哇捞到好东西」的时刻。`ROUND1_BRIEF` 要求的
「名称、短描述、用途的道具目录」（opus-items 的 `data/catalog.ts` +
`sim/inventory.ts`）**尚不存在**。

### 2.2 目标 —— 只有「别死」

开局约 150 秒水粮见底，玩家全部动机是被动求生。没有引导链
（首块地基 → 首台净水机 → 撑过首场风暴）、没有任务板、没有里程碑
奖励。休闲基建品类靠**连续的小目标**（下一格、下一座房、下一个岛民）
喂多巴胺，本作一个都没有。5 种建筑开局全可见全可造，无解锁进程，
10 分钟后体验同质化。

### 2.3 剧情/氛围 —— 零文案实体

游戏内叙事文本 = 标题页两行副标 + 结算 6 句死因文案，**局内为零**。
没有日记、没有广播、没有漂流瓶。`STORY.md`（fable-narrative）与
`src/story/**`（opus-story）均未落地。

### 2.4 岛民 —— 是个系数，不是人

「养活岛民」是品类名字的一半，但岛民在本作只是 `crewOf()` 返回的
一个整数：没名字、没脸、没话、不提请求；HUD 胶囊里的小人是唯一
可见形态，且喂养状态是全有/全无（`fed = starving ? 0 : crew`）。
招募是被动的（盖房 +1），玩家对「人」没有任何决策与情感投入。

### 2.5 加工 —— 资源图是平的

捞 4 种材料 → 直接花在 5 种建筑上，一步到头。没有二级配方
（塑料→滤芯、木板+绳→渔网、鱼→熟食）、没有加工建筑。手游同品类的
数值深度与「再玩 5 分钟」的钩子大半在加工链上。

### 2.6 次要结构缺口（非本轮根因，记录在案）

- 无局中存档：关标签页 = 丢一局。对生存计时玩法尚可接受，
  一旦加入任务/剧情进度就会变成硬伤。
- `refund`/`scrapValue` 在 sim 备好但没有拆迁按钮（玩家无法纠错布局）。
- 探索为零：海域固定一屏（`DEFAULT_BOUNDS` = 可见画布），无事件点。
- 浏览器实机键鼠走完一局的验收三轮都没关（Round 2/3 遗留）。

## 三、SOTA 差距分级

### P0（不做，本轮就等于没发生；全部对应 ROUND1_BRIEF 的硬要求）

1. **物品目录接进拾荒**（opus-items：`data/catalog.ts` + `sim/inventory.ts`）
   条目化漂浮物：每条有 id、名称、短描述、用途、稀有度；
   落地方式 = 在现有 `SALVAGE.weights` 掉落轴上扩展（普通件仍折算成
   四材料入库，特殊件进少量「珍品位」），**复用 `Resources`/`gain`，
   禁止并行第二套经济**。验收：捞取时 HUD/飘字能报出条目名，
   至少 12 条可辨认条目 + 1 类特殊件（漂流瓶或货箱）。
2. **一种接 sim 的新循环**（opus-play：`sim/expand.ts`）
   建议选**岛民请求**（“今天想吃鱼 / 缺 3 块木板修屋顶”→ 限时交付 →
   小额奖励 + 一句谢词），因为它同时救 §2.2（目标）和 §2.4（岛民是人）。
   必须是纯函数 + 事件出口（照 `ThreatEvent` 模式），走现有
   `pay`/`gain`，headless 可测。**只有文案没有资源进出 = 不合格。**
3. **轻剧情递送管道**（opus-story：`src/story/**`；文本源 fable-narrative
   `STORY.md`）：触发器挂在现成信号上——天数（`dayNumber`）、首次建成
   某建筑、首次 `pirate-killed`/`storm-strike` 事件——输出一条日记/岛民
   闲话到 UI 显示位（toast 或日志条，归 fable-sota 的 HUD 面）。
   语气按 SOTA_BAR：末世但不丧。验收：一局 5 分钟内至少见到 4 条
   不重复的局内文案，且触发条件来自 sim 状态而非定时器硬编码。
4. **目标链最小版**：3–5 个里程碑（首块地基 / 首台净水机 / 撑过首场
   风暴 / 木筏 ≥ 12 格 / 活到第 3 天），完成给小额材料 + 一句文案。
   可并入 2 的请求系统实现，不必单独立系统。
5. **目录隔离验收**（gpt-probe/gpt-test）：test/build/smoke/probe 全部
   指向 `games/sea`（现状已基本成立，13/13 绿），新增文件不得回流根
   `src/`；存档若加字段必须兼容读 `cww_sea_v1`。

### P1（强烈建议，P0 落地后的下一口）

6. 岛民个体化：名字池 + 颜色/表情差分，请求归属到具体岛民；
   HUD 胶囊按人显示饿态（替换现在的全有/全无）。
7. 加工链一层：1–2 个二级配方或一座加工建筑（如「厨房：2 鱼 → 5 食物
   + 短 buff」），吃掉 rope/plastic 的后期过剩。
8. 特殊漂浮物事件化：漂流瓶 = 剧情载体、密封货箱 = 随机奖励包
   （与 P0-1 的珍品位衔接）。
9. 拆迁/回收接入操作（`scrapValue` 已备好），玩家能纠错布局。
10. 局中进度存档（新键或 `cww_sea_v1` 加字段兼容读）。
11. SOTA_BAR 遗留：建造栏鼠标点选 `hitTestBuildBar`、海盗方向预告、
    浏览器实机走查一局并留录屏。

### P2（锦上添花）

12. 海域「事件点」：一屏内出现的可驶近浮标/沉船点，触发小事件——
    满足探索欲但**不做镜头滚动**（见 §四）。
13. 结算页展示本局新捞条目/完成请求数；成就页。
14. 天气变奏、BGM、岛民表情、结算数字滚动（SOTA_BAR P2 继承）。

## 四、明确不该做（负面清单）

1. **官方 IP 零接触**：陈小春肖像/姓名、益世界官方角色名、立绘、曲、
   照抄数值表。法律红线，简报三令五申。文案自创、数值自调。
2. **不重做开放世界**：不加镜头跟随、不做多岛屿大地图航行、不做
   Raft 式 3D。整个架构建立在「单屏一眼全局」上（无相机系统、
   `DEFAULT_BOUNDS` = 可见画布、漂浮物出画即无意义），推翻它等于
   重写 world/entities/input 三层，且毁掉休闲基建的阅读性。
   探索欲用 P2 的一屏内事件点满足。
3. **不发明第二套系统**：第二套网格（ARCHITECTURE 明令禁止）、
   第二套库存/经济（catalog 必须折回 `Resources` 轴）、
   会冲掉玩家纪录的新存档键。
4. **不重写已验收的 sim 循环**：economy/threats/rules 数值自洽且被
   13 项单测锁着，扩展一律走新文件（`expand.ts`/`catalog.ts`/`story/`）
   + 现成事件挂点，不改老文件签名。
5. **不越 OWNERSHIP**：session.ts/main.ts 只由父调度器接线；
   各代理只写自己的路径；游戏不搬回根 `src/`。
6. **不做偏基调的机制**：岛民微操走位（RTS 化）、永久死亡惩罚、
   血红恐怖化警报——违背「末世但不丧、轻松摸鱼」的既定基调。
